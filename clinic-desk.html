01 / THE TASK

Keep the front desk organized.

A clinic needs a clear way to register visits, find returning patients, track amounts received and print the saved visit without creating duplicate records.

02 / THE BUILD

Separate the records that matter.

The source application separates permanent patient IDs, visits and payments. It includes daily checkup numbers, fee rules, visit statuses, payment/refund records and backups.

03 / THE EXPERIENCE

Make the next action obvious.

The walkthrough shows a small fictional queue, record selection, completing a visit and a printable sample slip. It does not run PHP or persist clinic data in the browser.

IN THE SOURCE APPLICATION

Designed around
daily clinic work.

  • New and returning patient visit workflows
  • Separate patient, visit and payment identifiers
  • Daily checkup numbering and waiting/completed/cancelled states
  • Pending payments, collections and controlled refund records
  • Print-ready slips and reprinting saved visits
  • Admin/receptionist accounts, reports and local backups

Deployment and scope.

The supplied project requires PHP 8.1+ with PDO SQLite, a local web server and a writable data directory. GitHub Pages serves this case study and static walkthrough; it cannot host the original PHP backend.

No real patient data, live payments, SMS or WhatsApp delivery are connected here. Production use needs a separate deployment review, access controls, backup procedures and local operational requirements.
